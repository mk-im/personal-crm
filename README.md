# Личная CRM

Список людей, которых знаете лично: кто это, откуда знакомы, телефон, почта и о чём договорились. К карточке можно дописать заметку после разговора.

Живое приложение: [app.crmc.space](https://app.crmc.space). Лендинг: [crmc.space](https://crmc.space).

## Как запустить

1. Запустите Docker Desktop.
2. В папке проекта выполните `docker compose up -d` — поднимутся PostgreSQL и почтовая заглушка Mailpit.
3. `pnpm install`
4. `pnpm db:migrate`
5. `pnpm db:seed` — добавит 1000 тестовых контактов владельцу из `OWNER_EMAIL`, если у него ещё нет контактов.
6. `pnpm dev` и откройте http://localhost:3000

Настройки лежат в `.env` (образец — `.env.example`): строка подключения к базе, адрес приложения и секрет входа, почта владельца, параметры SMTP и адрес отправителя.

## Вход

Пароля нет. На странице входа вы пишете почту и получаете письмо со ссылкой; ссылка живёт 15 минут и открывается один раз. Первый переход по ссылке создаёт аккаунт. Сессия живёт 30 дней с последнего захода; «Выйти» в шапке завершает сессию только на этом устройстве. Каждый видит только свои контакты, заметки и группы.

Локально письма не уходят в интернет: их принимает Mailpit, страница заглушки — http://localhost:8025. На сервере письма отправляет SMTP Resend.

## Как выкатывается на сервер

Слияние в ветку `main` собирает образ, кладёт его в GitHub и на сервере сначала сохраняет копию базы. Имя файла начинается с версии, которая работала до этой выкатки: это метка образа приложения, тот же код коммита. После метки — дата и время копии, по всемирным часам. Файлы лежат в `/home/crm/personal-crm/backups`. Старые копии сами не удаляются.

В логе выкатки есть строка `Backup written` и путь к файлу. Дальше применяются миграции и поднимается новая версия. Если копию сохранить не удалось или миграции не прошли, работающее приложение не меняется. Если проверка `/health` не прошла, выкатка останавливается с ошибкой и сама назад не откатывается.

Чтобы выкатить новую версию, закоммитьте изменения, отправьте ветку и влейте её в `main`.

## Как восстановить базу

Восстановление запускаете вы на сервере. Версия приложения при этом не меняется.

1. Выберите файл в `/home/crm/personal-crm/backups`. Имя начинается с версии, которая работала, когда снимали эту копию.
2. На сервере выполните:

```
/home/crm/personal-crm/deploy/restore.sh /home/crm/personal-crm/backups/ИМЯ_ФАЙЛА.dump
```

3. Скрипт покажет файл и имя базы, которую заменит, и будет ждать слово `yes`.
4. Затем сохранит копию базы, как она есть сейчас, остановит приложение, удалит базу, создаст пустую и загрузит выбранный файл.
5. После этого снова запустит ту же версию приложения.

Если выбранный файл не читается как копия базы, приложение включится обратно, база останется как была. Если загрузка оборвётся после удаления базы, приложение останется выключенным. Копия, снятая перед восстановлением, лежит в той же папке `backups`.
