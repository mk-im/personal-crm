# Design

## Context

См. proposal.md — Why. Сейчас контакт — одна строка в `contacts`, список на главной один, поиск по имени и блок «Пора связаться» уже есть. Групп нет. Vitest в проекте не подключён, CI на PR нет: workflow только выкатывает `main`. Требования — `specs/groups/spec.md`.

## Goals / Non-Goals

**Goals:**

- Многие-ко-многим: человек в нескольких группах, группа без людей тоже хранится.
- Секции главной собирает одна функция. Её тесты не нуждаются в браузере и в базе.
- Страницы остаются серверными, как список и карточка сейчас. Цвета и отступы — только токены.

**Non-Goals:**

- Playwright, GitHub Actions для проверок, Testing Library.
- Цвет, описание, порядок «как создала».
- Создание группы из формы контакта.

## Decisions

1. **Две таблицы, не список названий в контакте.** `groups` (`id`, `name`) и `contact_groups` (`contact_id`, `group_id`, составной ключ). Оба внешних ключа с `on delete cascade`: удалили контакт — связи ушли, группы живы; удалили группу — связи ушли, контакты живы. Альтернатива — массив названий у контакта: переименование и «группа без людей» пришлось бы собирать обходом всех контактов.

2. **Название проверяет код, уникальность подстраховывает индекс.** Перед записью название обрезается. Пустое, «без группы» в любом регистре и повтор без учёта регистра (`toLocaleLowerCase('ru-RU')`) отклоняются с текстом ошибки. В базе уникальный индекс по `lower(name)`, чтобы два одновременных создания не прошли мимо проверки. Сравнение в коде, а не collation Postgres: так «Семья» и «семья» совпадают и на главной, и на странице групп, независимо от локали базы.

3. **Порядок секций и подписей — в коде, `localeCompare('ru')`.** Страница групп и главная сортируют одинаково. Внутри секции порядок людей уже есть: `listContacts` сортирует по имени. Альтернатива — `ORDER BY` в Postgres: при локали `C` русский алфавит разъедется с тем, что видит браузер.

4. **Секции не пишутся в базу.** Запрос контактов как сейчас, вторым запросом — связи этих людей с названиями групп. Функция `buildContactSections` получает людей и связи и возвращает секции: группы по алфавиту, только непустые, затем «Без группы», если есть кому там быть. Счётчик «Всего» / «Нашли» — число людей до раскладки по секциям, не число строк. Блок «Пора связаться» и его запрос не меняются: он по-прежнему над списком и скрыт, когда в адресе есть поиск.

5. **Сохранение контакта заменяет набор связей целиком.** В одной транзакции: если среди присланных id есть уже удалённая группа — ничего не писать и вернуть ошибку. Иначе сохранить поля контакта и выставить связи ровно на отмеченные группы. Форма шлёт id чекбоксами. Нового текстового поля для названия там нет. Если групп нет, форма показывает ссылку на `/groups` и всё равно сохраняет контакт.

6. **Страница `/groups` и ссылка «Группы» в шапке.** Создание, переименование и удаление — серверные действия. Удаление с тем же шагом подтверждения, что у контакта: сначала «Удалить», затем «Точно удалить?». Отмена — это не отправленная форма, действие удаления не вызывается.

7. **Подписи.** В строке списка под именем остаётся «откуда знакомы», ниже — названия групп через запятую. Нет групп — этой строки нет. В карточке поле «Группы»: названия или «не указано», как у пустых полей карточки.

8. **Тесты — Vitest на этих функциях, по одному на сценарий спеки.** Сначала красный тест, потом код. В браузере сценарии пройдёт Playwright отдельно, не в этом изменении. Новых библиотек кроме Vitest нет: он уже назван в CLAUDE.md, в `package.json` его ещё нет.

## Risks / Trade-offs

- [После миграции у всех текущих людей нет групп, главная станет одной секцией «Без группы»] → так и задумано: готовый набор не зашиваем. Группы пользователь заводит сам.
- [Человек в двух группах занимает две строки, счётчик при этом один] → счётчик считается до раскладки.
- [Отмена удаления не гоняется кликом в тесте] → тест проверяет, что без подтверждённой отправки действие удаления не выполняется. Клик по экрану — в Playwright.
- [Индекс `lower(name)` и проверка в коде могут разойтись на редкой букве] → ошибку пользователю всегда отдаёт проверка в коде; индекс только не пускает дубль.

## Migration Plan

1. Миграция создаёт `groups` и `contact_groups`. Строки `contacts` не меняет.
2. Выкатка как обычно: PR → merge в `main` → миграции → новый образ. Старые контакты остаются, связей нет.
3. Откат образа: старый код новые таблицы не читает, контакты на месте. Удалять таблицы — только вручную, если попросите.
